# inf-20100316 (Infdev 20100316)

Support added after inf-20100313. Protocol number 13. SHA-256 of the original jar:
`a363943f5e2c147ab0515930317dd535e9a2229fa0eb952c73fb6f078cfbda20`.

## What the build changes (jar compared with 20100313, and the wiki page)

- The world class is called `net/minecraft/a/a/e` again (it was `f` in 313); the chunk provider, chunk (`e/d`),
  nibble array (`e/c`) and generator (`e/e`) keep their names, the provider interface lost its no-argument method.
- Chunk fields moved one letter: blocks `b`, metadata `d`, sky light `e`, block light `f`, height map `g`,
  lowest height `h`, chunk numbers `i`, `j`. `b()` (redraw) is gone; `a()` still works out the heights and light.
- World: player field `a` (was `b`), time `j` still, the day is **24000 ticks** (12000 in 313, the wiki: 20 minutes), the
  region-dirty method `a(IIIIII)` is gone: the world's listeners (field `h`, interface `a/a/b`) are called directly.
- Render manager: the camera position is now static (`b`, `c`, `d`) and `RenderManager.a(entity, partial)` subtracts it
  itself, so the players must be drawn with their world coordinates (313 needed a translation by the camera).
- Terrain generator: identical code to 313 (compared in bytecode), so the same seed gives the same land; only the
  flower scatter differs between runs (as in 313). Generated chunks of 313 and 316 were compared: the blocks differ only
  by flowers.
- Game: entities work again (block drops), an arrow that hits a block makes a mob, TNT is primed but does not explode;
  opening the inventory no longer crashes. These live in the client's own game; the server has no items or mobs.
- Client class names of the menus, renderer and tick are unchanged: the hooks of 313 apply as they are
  (`ClientPatcher.createTransformer316`).

## Items on the ground (found by testing)

The game of each client runs item entities (`net/minecraft/a/c/c/b`). The client hooks the world's add-entity method
(`ClientPatcher.createTransformer316`) and tells the server about each new item (`DROP_SPAWN` 0x35: id, count, damage,
position, motion); the server numbers it and sends it to the other players, whose clients make a copy. When an item
entity is dead (picked up, too old) the client sends `DROP_REMOVE` 0x36 and the others remove their copy. Copies can be
picked up too. Items already lying around when a player joins are not sent to him.

Other fixes: the world's listeners (the renderer) are in field `p` (not `h`): chunks were not redrawn when they arrived
(black holes until a block was broken). The inventory report of the clients kept only ids up to 255, which dropped the
tools and the bow at the next login; it keeps ids up to 2000 now (saved `.inv` files made before still lack them).

## Arrows, animation, what 316 itself does not have

- Arrows: the shown players are not in the world's entity list, so arrows fly through them. The client follows the arrows
  it shot (class `a/c/d/a`, stuck flag `Q`); one that crosses another player's box sends an attack of 4 to the server
  (PvP rules of the server apply) and the arrow is removed. Other players do not see the arrow itself.
- Walking animation of the other players never ran (builds 227, 313, 316): the "in the air" test looked at the block at
  head height instead of under the feet. Fixed in the three clients.
- The mobs that an arrow makes (sheep, pig, skeleton, creeper, spider, zombie) are shared: the owner's client reports them
  (`MOB_STATE`, with the look: head and body direction, walking, hurt and death time, fire, health) and the other clients draw
  copies. A hit on a copy is carried out by the owner's game; when the owner leaves, another game takes the mob over
  (`MOB_ADOPT`). Pick-ups of shared items are decided by the server (`DROP_CLAIM`). The mobs do not burn in daylight: the game's
  zombie and skeleton code discards the brightness it computes.
- Knockback between two players on exactly the same spot gave NaN motion and the server kicked the victim ("Invalid
  position"): the clients reset NaN motion after a hit.
- The jar has no explosion code: the creeper only has its fuse sound and TNT does nothing, also in single player. Fire
  cannot be punched out either (the fire block has no selection box: `c()` and `a(III)` return false/null).
- Arm swing of other players is not shown: this build's player model has no swing animation.

## Parts

- Server: `server/bridge316/TWBridge316.java` (the 313 bridge with the names above, no relight call).
- Client: `client/mod316/` (`TW316Client`, `TW316Launcher`).
- World takeover: 313 -> 316 and 227 -> 316 (`WorldConverter.supportsStep`); tested with a 313 world of 81 chunks:
  taken over, chunks byte for byte equal in blocks, light, metadata and heights.
- Plugin API: `api/inf-20100316/` (`net.thewellodev.api316`: the 227 API plus block data and world time), server view in
  `server/src/.../api316`, the four plugins in `plugins/inf-20100316/`, see `docs/plugin-api/inf-20100316.md`.
