# inf-20100325-1640 (Infdev 20100325-1640)

Support added after inf-20100321 (the build 20100325-1545 between them has no known copy). Protocol number 16. SHA-256 of the
original jar: `1942c49c85167375182b4d181e71f2a199f223ae8f442332c4dbfaa5596c20a0`.

## What the build changes (jar compared with 20100321, and the wiki pages of 1545 and 1640)

- Wiki, 1545 (lost): caves re-implemented, ores in blobs, block ticks re-implemented (leaves decay, grass spreads, fire spreads,
  flowers pop off without sunlight), particles at the edges of water, furnaces "as before Infdev", stone slabs make double slabs,
  the duplicate login detection is gone. Wiki, 1640: cave generation no longer costs performance; flowers that see the sky no
  longer die.
- **Names:** the classes moved again. The world class is `net/minecraft/a/a/g`; the blocks are in `a/a/c` (the block base class
  is `a/a/c/x`); the tile entities in `a/a/c/a` (chest `c`, furnace `b`); the generator is `a/a/a/b` with its noise classes in
  `a/a/a/b` and the cave classes in `a/a/a/a`; the light-type enum is `a/a/e`. The chunk, its nibble array and the provider
  interface keep their names (`a/a/e/d`, `c`, `a`). In the client, the title screen is `q`, the tick method of the main
  class is `f` (as in 20100320) and the settings class `p`.
- **World members:** player `b` (was `a`), time `l`, sky darkness `p`, provider `u`, listeners `t`, light queue `i` and its
  drain method `e()` (was `d()`), tile get `h(III)`, light `f(III)`, the random `e`. Chest and furnace slots are in `e`, the
  furnace ints in `f`, `g`, `h`.
- **Block ticks:** `g.f()` is the world tick: the sky darkness and the time of day, up to 200 scheduled ticks (a list `k` of
  entries with a delay), and a sweep of 32000 tries around the world's player field (`b`): a random position, a block flagged
  in `x.d` is asked to tick (`x.a(world, x, y, z, random)`). `g.k(x, y, z)` is a second sweep of 1000 tries for the blocks' look
  (particles, `x.b`), `g.a()` tells whether it is day (darkness below 8: flowers use it).
- **Session check:** gone. The settings class (`client/k`) lost its session field, and the main class its poll thread.
- Block and item ids are the same as in 20100321 (checked with the game's own tables).

## What the server and the client do about it

- **The server ticks the blocks** (`TWTick`, `TWBridge325.blockTicks`): every tick it runs `g.f()` with a stand-in player, so the
  time, the darkness and the scheduled ticks work; the sweep of 32000 random tries is cut out of the method (the game would
  make every chunk within 128 blocks of the player to find blocks) and done by the bridge over the chunks it holds: 8000 tries
  for each player in a square of 129 blocks, which is the game's rate per block. Hooks in the world class report the blocks that
  change during the tick (they are sent to the players) and the items that blocks drop (they become shared items of the server's
  own slot, 2047, shown to the players near them; the first game that asks for one gets it).
- **The client does not tick blocks:** the patcher empties the scheduled list at the start of the world's tick and changes the
  bound of the random sweep from 32000 to 0. Everything else of the tick (time, darkness) runs, and `g.k` stays (particles).
- **Client changes:** the title screen is `q`; the hook that removed the online check of the set-world method is not needed; the
  settings class passes the session id through `thewellodev.token` (see `ClientPatcher.createTransformer325`).
- Plugin API: `net.thewellodev.api325`, and the four bundled plugins.
- World takeover: from 321, 320, 316, 313 and 227. The chunk files are the same, and a chunk that was made by an older build
  stays as it was made (a chunk of solid rock stays solid rock): only land made after the takeover has the caves and ore blobs
  of this build. The caves and ore blobs are made by the populate step, and the setting `upgrade-old-terrain=true` lets that step
  run once on each taken-over chunk (the old and the new land then fit, but the old land changes: caves, ores and more trees).
- Furnaces: the server ticks them (`TWBridge325.syncFurnaces`); the client's tile tick only knows the furnace that is open.
