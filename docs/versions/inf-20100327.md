# inf-20100327 (Infdev 20100327)

Support added after inf-20100325-1640 (the build 20100325-1545 and others between them have no known copy). Protocol number
17. SHA-256 of the original jar: `c696d187821b9034046e4572dfdb579a60b80530ff02598aadb6322e8ad8b247`.

## What the build changes (jar compared with 20100325-1640, and the wiki page of 20100327)

- **The Alpha level format.** The game saves its worlds again (it did not in the builds before). A world is a folder with a
  `level.dat` and the chunk files in folders named by base 36 numbers (see below). The game saves when a world is closed and
  every 200 ticks.
- **A new terrain generator.** The old 2D noise maps are gone; new noise generators ("low", "high" and "selector" noise)
  make the land. The generator has no caves and no flowers yet (the wiki says so, and the classes agree), the sea level is
  64 (it was 65), and the Far Lands appear where the noise overflows (about 12.5 million blocks from the origin).
- **Signed chunk numbers.** The world finds the chunk of a block with `x >> 4` (a signed shift); the builds before used an
  unsigned shift, so a chunk at a negative coordinate had a huge positive number.
- **Gameplay:** furnaces smelt in 4 seconds (it was 8), new worlds give no items to start with, the player always starts at
  0, 64, 0 and is moved up to the nearest free space, a player who dies drops the inventory and respawns at the spawn point
  (the game used to reload the last save). The title screen has "Single player" (a list of worlds to load, create and
  delete) and a greyed "Multi player".
- **Entities can be saved** (every entity class got save and load methods and a name). Nothing of this is used in the world
  files yet: the chunk files hold no entities, only tile entities.
- Block and item ids are the same as in 20100325-1640: every block and item class is identical (checked class by class).
  The world's tick (time, scheduled ticks, the sweep of random ticks) is the same code, except that the time is a long now.

## The world files

```
<world>/level.dat                      GZIP NBT: compound "Data" with RandomSeed, SpawnX, SpawnY, SpawnZ, Time, SizeOnDisk,
                                       LastPlayed and Player (the single player's entity)
<world>/<X mod 64>/<Z mod 64>/c.<X>.<Z>.dat   GZIP NBT: compound "Level" with xPos, zPos, LastUpdate, Blocks (32768 bytes,
                                       index x << 11 | z << 7 | y), Data, SkyLight, BlockLight (nibbles), HeightMap (256
                                       bytes) and TileEntities
```

`X` and `Z` are the real, signed chunk numbers; every number in a file name and in a folder name is written in base 36 with
`Integer.toString(n, 36)` (so a negative number has a minus sign), and the folder names use `n & 63`. For example the chunk
(-1, 0) is `1r/0/c.-1.0.dat`. The folder is the one the game's own single player uses (`saves/<name>`): **a world of this server
can be opened in the game's single player menu** (copy `worlds/inf-20100327/<level>` into the saves folder), and a world of the
game can be put into the server's `worlds/inf-20100327/` folder. The chunk files of the build carry no marker for "populated":
the game populates a chunk again when it loads one next to it (the wiki lists this: ores and trees regenerate after a load).
The server reads a chunk from a file as final and never populates it again.

## What the server and the client do about it

- **Bridge** (`TWBridge327`): as `TWBridge325` (the chunk provider is replaced by the bridge's own, which keeps the chunks in a map and
  makes new ones with the game's generator; the bridge populates, lights, ticks blocks and furnaces), with the names above, the
  signed chunk numbers, and the Alpha files written and read by the bridge itself (it uses its own NBT code, `TW227Nbt`).
  The game's own saving is cut out of the world class when it loads (`GameClassLoader`: the private `a(boolean)` does nothing),
  and the world is made with an empty scratch folder that is removed at once. The game's own world class reads a world made by
  the server and sees the same blocks as the files hold (checked with a test program).
- **Spawn point of a new world:** as in the game's single player: 0, 0, starting at height 64 and moved up until there is free space.
  Water counts as free space, so a world with sea at the origin starts the player in the water.
- **Takeover from an older build:** see below.
- **Client:** the title screen's greyed "Multi player" becomes "Multiplayer..." (the game's "Single player" stays: this build
  saves its own worlds); the pause menu's "Quit game" becomes "Disconnect" and "Change world" is switched off; the death
  screen's "Title menu" is "Disconnect". The world of the mod is made with a scratch folder, and the world's save method is cut
  out of the class by the patcher, so a multiplayer session writes nothing to the disk. The hooks that need names are in
  `ClientPatcher.createTransformer327`.
- Plugin API: `net.thewellodev.api327`, and the four bundled plugins.
- Game modes (creative, spectator), shared items, mobs, explosions, chests and furnaces: as in 20100325-1640.

## World takeover into 327

From 325-1640, 321, 320, 316, 313 and 227. The older worlds keep their chunk files in the world folder itself (`c.X.Z.dat` with
decimal numbers); 327 keeps them in the Alpha layout, so a chunk is **converted when it is first needed**: the bridge reads it
from the old folder and writes it in the new layout. A chunk that has its light and needs no change is copied as the file it is;
a chunk of 227 (which has no light) is read, lit by the game's own code and written. The converted chunk keeps what it has: a
chunk that was solid rock stays solid rock, and what an older build made is never populated again. Only land made after the
takeover is made by the new generator (new noise, sea level 64, no caves), so the edge between old and new land is visible.

`/convertworld` converts the chunks nobody has visited, a few in each tick (the tick takes at most about 20 ms for it), and
drops each chunk from memory after it was written: a world of any size can be converted with the server running and with
little memory (tested with 6561 chunks and 200 MB of heap). When it is done the old folder is not read any more (and can be
deleted). With `upgrade-old-terrain=true` the populate step of the new generator (trees and ores; there are no caves in this
build) runs once on each taken-over chunk.

The old world is never modified: the server of the old build still opens it as before.
