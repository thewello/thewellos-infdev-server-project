# inf-20100321 (Infdev 20100321)

Support added after inf-20100320. Protocol number 15. SHA-256 of the original jar:
`9dd5ed05f557d508766d8b9d4fd3f77adc69c1943fd47f51058191ab81fc55bf`.

## What the build changes (jar compared with 20100320, and the wiki page)

- The wiki lists one addition (**duplicate login detection**) and one fix (the game no longer returns to the title screen after
  generating a world offline).
- **World code:** every class under `net/minecraft/a/` (world, chunks, generators, blocks, items, entities, tiles) is
  byte-identical to 20100320. The server bridge is therefore the bridge of 320 (`TWBridge321`), and everything the 320 notes
  say about the world, terrain, populate step, chests, furnaces, explosions, items and mobs holds here
  (see [inf-20100320.md](inf-20100320.md)).
- **Client:** one class moved in the package `net/minecraft/client/`: a new class `o` (a lookup table of an enum) pushed the
  names `o`, `p` and `q` up by one: the title screen is `r` (it was `q`), the settings class is `q` (it was `p`). A new
  screen `c/s` shows "Session conflict!". In the main class `d` the tick method is `g` (it was `f`) and some public methods
  moved by one letter (`b` to `c`, `c` to `d`, `d` to `e`).
- **Session check (the new feature):** a daemon thread (`client/n`) calls `d.b(d)` every 30 seconds. That method reads
  `http://<address>/poll.jsp?...` (a server of the time, long gone) and stores a time in the static field `d.E`. The main
  loop compares the tick time `K` with `E` and opens `c/s` when the difference is more than 6000 or negative. When the poll
  gets no answer, `E` is not updated (this is read from the bytecode; the original game was not run without the patch).
- The **applet** no longer keeps a reference to itself in the main class (field `M` removed); the stop method moved into `d.b()`.

## Bridge and client mod

- `TWBridge321` and `TW321Client` are the 320 files with the names of this build. The client mod differs in one name:
  the title screen is `net/minecraft/client/r`.
- The patcher (`createTransformer321`) uses the hooks of 320 with these changes: the tick hook is in `d.g`, the title screen
  hooks are in `r`, the poll method `d.b(d)` is replaced by an empty body (the thread stays alive but does nothing, and the
  game contacts no server), and the first thing the tick does is `d.E = d.K`, so the session check always passes. The
  hook that removed the online check of the set-world method does not exist for this build (the method has no such check).
- The build is detected by `net/minecraft/client/r.class` together with `net/minecraft/client/c/s.class`.
- World takeover: from 320 (identical code, the chunks are read as they are), and from 316, 313 and 227 as into 320.
- Plugin API: `net.thewellodev.api321` (see [../plugin-api/inf-20100321.md](../plugin-api/inf-20100321.md)); the plugins
  of 320 exist for 321 under `plugins/inf-20100321/`.
