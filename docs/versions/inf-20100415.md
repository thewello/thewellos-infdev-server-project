# inf-20100415 (Infdev 20100415)

Support added after inf-20100414. Protocol number 21. SHA-256 of the original jar:
`bef3eadbe765604f0b578bfc757adc5c73fb4d449ac1a02355c9f7bd1af97e47`.

## What the build changes (jar compared with 20100414, and the wiki page)

The wiki page says: mobs now spawn naturally, most entities are saved with the world (arrows are not), the giant has its own texture,
custom skins work again, and the lighting code was fixed (lighting updates properly, less memory, blocks that were not exposed to the
sky when the land was made, such as cliff overhangs, are no longer completely dark). The jar has 3 more classes than 20100414 and
about 100 changed classes; the class and member names were compared with a structural match (the shape of each class with the
game's own names left out):

- **Mobs can be made again.** Every mob class (`a/c/a/*`, `a/c/b/*`) and the item entity (`a/c/c/b`) has a constructor that takes the
  world, which the builds 20100413-1953 and 20100414 did not. The game's mob spawner works, so every game makes mobs of its own and
  the server shares them as in 20100330-1611 (the client mod finds the constructors by itself).
- **World class `a/a/g`** keeps the methods of 20100414 (the tick is `i()`, the light queue is worked off by `h()`) and has two new ones,
  `a(List)` and `b(List)`, which add and remove the entities of a chunk; the world listener interface (`a/a/a`) got two methods for
  entities that are added and removed. The fields moved: time `b` (was `c`), the player `c` (was `d`), the list of tile entities `a`
  (was `b`), the light queue `l` (was `m`); the list of entities is private (`m`).
- **Client classes moved by a letter:** the game's settings `client/k` (was `j`), the title screen `client/q` (was `p`), the game
  renderer `client/a/e` (was `a/d`), the HUD `client/c/n` (was `c/m`), the sorter of the renderer `client/a/l` (was `a/j`) and the texture
  manager `client/a/k` (was `a/i`). The entity classes keep the names of 20100414.

## What the server and the client do about it

- **Bridge** (`TWBridge415`), **client mod** (`TW415Client`) and **plugin API** (`net.thewellodev.api415`) are the ones of 20100414 with
  the names above. The class loader seeds the random numbers and cuts out the save method, the random block tick sweep and the
  sand fall with the same classes as in 413. The server still holds no entities: what the world adds during a tick or from a chunk is
  not kept (the games own the items and the mobs).
- **Client patcher:** 20100415 is recognised by the class `client/a/l` (20100413-1953 and 20100414 do not have it), gets the hooks of
  413 with the names above (`ClientPatcher.createTransformer415`) and keeps the game's mob spawner, because the mobs can be made.
- **World takeover:** the same Alpha level format. From 20100414 the chunk files are moved over as the files they are, in the
  background (`/convertworld`, a few chunks in each tick, and each chunk when it is needed); from older builds as into 414. The older
  world is deleted when every chunk is over (`delete-old-world`). Mobs that the game saved in its chunk files are not read.
- Plugin API: `net.thewellodev.api415`, and the four bundled plugins. Shared items, mobs, game modes, explosions, chests and furnaces
  as in 20100413-1953 and 20100330-1611.
