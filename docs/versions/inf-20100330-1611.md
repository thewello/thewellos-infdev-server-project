# inf-20100330-1611 (Infdev 20100330-1611)

Support added after inf-20100327 (the build 20100330-1203 between them has no known copy). Protocol number 18. SHA-256 of the
original jar: `3beb70d42f81f717f04a8c47b847854eda4aabe5b5a23d62e6b9ef86a8aec64d`.

## What the build changes (jar compared with 20100327, and the wiki pages of 1203 and 1611)

The jar has the same class names as 20100327, and 209 of its 234 classes are identical; what moved is a few members.

- Wiki, 1203 (lost): furnaces smelt in 8 seconds again (4 in 20100327); a new tag **TerrainPopulated** is written into the chunk
  files, so trees and ores no longer regenerate when a world is loaded; containers (chests and furnaces) save reliably; the light
  of slabs is right; the top of the world is no longer fully lit and mass light updates no longer hang the game; broken blocks
  no longer keep their data value (a crop planted where a crop was no longer starts grown). Wiki, 1611: the clouds no longer follow
  the player along x and z. (The wiki lists one bug: placing torches sometimes crashes the game; "more information needed".)
- **The populated flag.** The chunk class got a public flag `d` (TerrainPopulated; it was the "changed" flag, which is `e`
  now), so the private fields moved by one: blocks `f`, world `g`, metadata `h`, sky light `i`, block light `j`, height map `k`,
  lowest height `l`, tile entities `m`. The game's provider populates a chunk whose flag is false when its neighbours exist, and
  sets the flag; the chunk's save method writes the flag as the byte tag `TerrainPopulated`, and its load method reads it (false
  when the tag is missing: a world of 20100327 is populated again when it is loaded in the game itself).
- The tree and ore feature classes got a new method that returns a boolean (placed or not); the tile entities, the inventory and
  the container interface got one more method each (the wiki says containers save reliably now), and the world got a method
  `l(x, y, z)`; the light code of the world and the furnace code changed. All other names, the block and item tables, the world tick and the world files are as in 20100327.
- Because the jars have the same class names, the build is recognised by its checksum (server) and by the chunk class knowing the
  tag TerrainPopulated (patcher).

## What the server and the client do about it

- **Bridge** (`TWBridge330`): `TWBridge327` with the new chunk fields. The bridge sets the chunk's populated flag after it ran the
  populate step, writes the tag TerrainPopulated (always 1: the bridge writes only chunks that are final), and reads it: a chunk
  file with the tag 0 (a chunk that the game's single player saved before it was populated) is populated when it is needed, a chunk
  file without the tag counts as populated and is never populated again, as before.
- **World takeover:** the world of this build is in the same Alpha level format as 20100327. From 327 the chunk files are not
  converted but moved into the new world as the files they are (the folders and names are the same), a chunk at a time when it is
  needed, and the rest by `/convertworld`, a few in each tick; from older builds as into 327. The older world's folder is read in
  either layout (flat folder of the builds before 327, or Alpha layout). When every chunk is in the new world the older world is
  deleted (`delete-old-world`).
- **Client** (`TW330Client`): `TW327Client` with the new chunk field names. The patcher uses the hooks of 327 (same names).
- Plugin API: `net.thewellodev.api330`, and the four bundled plugins.
- Furnaces smelt on the server (8 seconds per item, the game's own code), game modes, shared items, mobs, explosions and chests: as in 327.
