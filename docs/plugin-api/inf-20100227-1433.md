# Plugin API for inf-20100227-1433

A Bukkit-style API made for Infdev inf-20100227-1433. Plugins are jars with a `plugin.yml` at the root and a main class
that extends `Plugin227`. The API only has what this build has: blocks, players, chat, commands, health, PvP, the game
mode (survival or creative with flying) and teleporting. It has no inventory, no items, no items on the ground, no mobs,
no block metadata and no day and night (this build has none of them).

The other builds have their own APIs (see the [overview](README.md)): a plugin is made for one build and the
server only loads plugins of the build it runs.

## Setup

Add `TheWellosInfdevServer-API-inf-20100227-1433.jar` as a compile-time dependency. Do not put it in the server; the server
already contains it.

```sh
javac -cp TheWellosInfdevServer-API-inf-20100227-1433.jar -d out $(find src -name '*.java')
cp src/plugin.yml out/
jar cf MyPlugin.jar -C out .
```

Copy `MyPlugin.jar` into the server's `plugins/` folder and restart. The jar also holds the classes every build shares
(the plugin framework, commands, config, scheduler, `ChatColor`, the event base classes) and the classes of the other
build's API (`net.thewellodev.api.Server`, `World`, `Player`, `Block`, `Material`, `ItemStack` and their events). **Those
last ones are not for this build: use the types of `net.thewellodev.api227`.**

## plugin.yml

`api: inf-20100227-1433` is required. Without the line the server takes the plugin as one for inf-20100630-1340 and
does not load it on this build (the console says so).

```yaml
name: HelloPlugin
version: 1.0
api: inf-20100227-1433
main: com.example.hello.HelloPlugin
author: Your name
description: Example plugin
depend: []        # required plugins
softdepend: []    # optional plugins loaded first
commands:
  hello:
    description: Greets the player
    usage: /<command> [name]
    aliases: [greet]
    permission: hello.use   # ".use" and ".default" are open to everyone; others need operator status
```

## Example

```java
public class HelloPlugin extends Plugin227 implements Listener {

    @Override
    public void onEnable() {
        getConfig().addDefault("welcome-message", "&aWelcome, %player%!");
        saveConfig();                                   // plugins/HelloPlugin/config.yml
        server().getPluginManager().registerEvents(this, this);
        server().getScheduler().runTaskTimer(this, new Runnable() {
            public void run() { server().broadcastMessage("&6Announcement!"); }
        }, 20L * 60, 20L * 60 * 5);                     // after 1 minute, then every 5 minutes
    }

    @Override
    public boolean onCommand(CommandSender sender, Command cmd, String label, String[] args) {
        if (cmd.getName().equals("hello")) {
            sender.sendMessage(ChatColor.YELLOW + "Hello!");
            return true;
        }
        return false;                                   // false shows the usage message
    }

    @EventHandler
    public void onJoin(PlayerJoinEvent e) {             // net.thewellodev.api227.event.player.PlayerJoinEvent
        e.getPlayer().sendMessage(getConfig().getString("welcome-message").replace("%player%", e.getPlayer().getName()));
    }

    @EventHandler(priority = EventPriority.HIGH, ignoreCancelled = true)
    public void onBreak(BlockBreakEvent e) {            // net.thewellodev.api227.event.block.BlockBreakEvent
        if (e.getBlock().getType() == Material227.BEDROCK) e.setCancelled(true);
    }
}
```

## What this build has

- **World:** blocks 0 to 51 (stone, grass, dirt, ... cloth colours 21 to 36, flowers, mushrooms, gold and iron blocks,
  slabs, brick, TNT, bookshelf, mossy cobblestone, obsidian, torch, fire), no metadata. `World227.getSeed()` is the seed
  the terrain is made from (the server's `level-seed`); `getLoadedChunkCount()` of the server tells how many chunks are
  in memory (the game keeps every chunk it made).
- **Players:** health (0 to 20; the client reports it, the server keeps it), death and respawn, game mode 0 or 1
  (creative: flying, no damage; operators only), PvP (hits between players), teleporting, display name, kicking.
- **Chat and commands:** chat format (`%1$s` display name, `%2$s` message), command preprocessing, plugin commands.

Not in this API because the build has none: inventory and items, items on the ground, mobs, TNT entities, block
metadata, tile entities, day and night.

## Events

The server fires its usual events; the same thing is then announced to the plugins of this build with the classes of
`net.thewellodev.api227.event`, and what the plugins change comes back: cancelling, the chat format and message, join,
quit and death messages, a move's destination, the damage of a hit, the respawn location, the refusal of a login.

## Added in 2.2.0

Nothing was removed or changed: plugins made for an earlier version keep working. New methods:

- `Player`: `getEyeLocation()` (the feet location plus 1.62), `getTargetBlock(maxDistance)` (the first block on the line of
  sight that is not air or liquid, or `null`), `getLoginTime()` (milliseconds since 1970).
- `World`: `getNearbyPlayers(center, radius)` (nearest first), `fill(x1, y1, z1, x2, y2, z2, typeId, data)` (at most 32768
  blocks, returns the number of blocks that changed, throws `IllegalArgumentException` for a box that is too large or a
  block that does not exist), `getDayLength()`, `isDay()`, `isNight()`, `getBlockLightAt(x, y, z)` and `getSkyLightAt(x, y, z)` (the stored light, 0 to 15; -1 when the
  build has no light or the chunk is not in memory).
- `Server`: `getOperators()`, `getBannedPlayers()`, `getWhitelistedPlayers()`, `broadcastMessage(message, permission)`
  (only players with the permission, and the console), `matchPlayers(partialName)`, `getUptimeMillis()`.

Plugin commands: the `CommandSender` that a plugin command gets is now the player type of the build (`Player227`)
when a player runs it, so `sender instanceof Player227` works. (Before 2.2.0 it was the server's own player object, and
such a test was always false.)

## Added in 2.3.0

Nothing was removed or changed: plugins made for an earlier version keep working. The new methods follow the names of the Bukkit
API of the time and only exist where this build has what they need. Most of them are `default` methods of the interfaces.

- `net.thewellodev.api.util.BlockFace` (shared): `NORTH` (towards a lower x), `EAST` (lower z), `SOUTH` (higher x), `WEST`
  (higher z), `UP`, `DOWN`, the four corners and `SELF`, with `getModX()`, `getModY()`, `getModZ()` and `getOppositeFace()`.
  `net.thewellodev.api.util.Vector` (shared): `add`, `subtract`, `multiply`, `length`, `distance`, `dot`, `crossProduct`,
  `normalize` and `clone`.
- `Location227`: `add(location)`, `subtract(location)`, `subtract(dx, dy, dz)`, `multiply(factor)`, `zero()`, `length()`,
  `lengthSquared()`, `toVector()`, `getDirection()` (a vector of length 1 from the yaw and the pitch), `locToBlock(double)`,
  `equals` and `hashCode` (the world, the position and the look direction).
- `Block227`: `isEmpty()`, `isLiquid()`, `getRelative(face)`, `getRelative(face, distance)`, `getFace(block)` (the side on
  which another block touches this one, or `null`), `getChunkX()`, `getChunkZ()`.
- `World227`: `getBlockTypeIdAt(location)`, `getHighestBlockYAt(location)`, `getHighestBlockAt(x, z)`,
  `getHighestBlockAt(location)`, `getMaxHeight()` (128), `getChunkCoord(blockCoord)`.
- `Server227`: `getViewDistance()` (`view-distance`), `getSpawnRadius()` (`spawn-protection`), `getWorlds()` (the one world,
  in a list), `getWorld(name)`, and the Bukkit names `getOnlineMode()`, `hasWhitelist()`, `matchPlayer(name)` and
  `broadcast(message, permission)`.
- `Player227`: `performCommand(commandLine)` (as if the player typed it), `teleport(otherPlayer)`.
- Events: `BlockPlaceEvent.getBlockPlaced()` and `getReplacedTypeId()` (the type of the block that is replaced: the event
  comes before the change), `PlayerRespawnEvent.isBedSpawn()` (always `false`: the build has no beds).

What the Bukkit API has and this build has not is not in the API: no inventories or items (before 630), no entities other than players
(and the items and mobs the build has), no several worlds, no chunk objects, no redstone, no recipes, no custom
world generators.

## Rules

- Call the API from the main server thread only (events, commands, scheduler tasks).
- Colour codes: `&0`-`&f` (the console strips them).
- `World227.setBlockTypeId` loads or generates the chunk, changes the block and sends the change to the players.
- Operators are exempt from the checks of the bundled plugins; creative mode is for operators.

## Plugins for this build

The bundled plugins are in `optional-plugins/inf-20100227-1433/`: NameColor (chat colours), NoIllegals (banned blocks),
TheWelloNoCheat (anti-cheat: movement, flying, reach, attack rate, chat spam) and TheWelloNoLagg (memory guard, chunk
watch, TPS alerts). OpenInv has no counterpart: this build has no server-side inventory to show.

## Versioning

The API follows the server (1.0.0). The package `net.thewellodev.api227` belongs to this build only; other builds get
their own package.
